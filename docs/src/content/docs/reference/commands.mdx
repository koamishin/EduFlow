Run any command with `--help` for the authoritative option list. All commands bind the
installation institution fail-closed; `sync` is refused where a durable queue is required.

## Installation & identity

| Command | What it does |
| --- | --- |
| `app:install` | Create the single institution identity, roles/permissions, zero autonomous thresholds; disables registration/impersonation/AI. `--institution= --country= --timezone=UTC --locale=en --currency=USDC --adopt-institution=` (alias `eduflow:install`) |
| `app:bootstrap-admin` | Create the first super-admin interactively (hidden password prompt). `--name= --email=` (alias `eduflow:bootstrap-admin`) |
| `setup:starter-kit` | Scaffold/rename the starter-kit identity (icons, authors, Docker toggle) |
| `install:features` | Apply chisel feature markers (`chisel.php`) — see the composer `--no-scripts` warning |

`app:install` never migrates, resets data, seeds demo records, generates keys, creates
wallets or calls external providers. Repeating identical setup is a no-op; changed
identity metadata is refused rather than overwritten.

## Diagnostics & Circle session

| Command | What it does |
| --- | --- |
| `lepton:doctor` | **Run this first.** Verifies binaries, session, treasury, chain reads and ledger parity. `--transfer= --to= --skip-transfer --adopt-agent-wallet` |
| `lepton:login` | Circle agent session (email OTP; owned by the Circle CLI). `lepton:login <email>` sends the OTP, `--request=<id> --otp=<code>` completes it, `--status` reports both networks |
| `lepton:status` | Chain, block, balance and limits for an address — `--address=0x…` (mainnet-only `wallet limit`, see [Troubleshooting](../../reference/troubleshooting/)) |
| `lepton:transfer` | Single transfer — `0x… --amount=1.00 --from=0x…`; `--estimate` dry-runs |

Mainnet and testnet sessions are independent; `isAuthenticatedFor('ARC-TESTNET')` is the
authoritative check before a testnet transfer.

## Finance policy, evidence & drafts

| Command | What it does |
| --- | --- |
| `app:prepare-finance-policy` | Draft an immutable policy version. `{version} --actor= --reserve= --auto-limit=0 --daily-limit=0 --max-fee=0` (exact USDC; alias `eduflow:prepare-finance-policy`) |
| `app:activate-finance-policy` | Activate a reviewed policy version. `{policy} --reviewer= --expected-activation=` — requires a separate reviewer and explicit `none` for first activation (alias `eduflow:activate-finance-policy`) |
| `app:draft-institution-policy` | Persist an editable institution-policy draft (never publishes or enables runtime). `{author} --save` (alias `eduflow:draft-institution-policy`) |
| `app:prepare-vendor-payment` | Prepare one immutable full-bill USDC draft. `{invoice} --actor= --wallet= --max-fee=0 --intent-key=` (UUID reused for retries; alias `eduflow:prepare-vendor-payment`) |
| `app:finance-preview` | Read-only treasury/cashflow preview without students. `--days=30` (1–90; alias `eduflow:finance-preview`). Always `can_execute=false` |

Policy activation is not payment approval; draft preparation is not human sign-off.
Shell access is the attribution boundary — CLI staff IDs are not proof of personal
authentication or MFA.

## Background dispatch & reconciliation

| Command | Schedule | What it does |
| --- | --- | --- |
| `app:dispatch-finance-workflows` | every minute | Recover and dispatch bounded read-only planning/review work |
| `app:dispatch-payment-submissions` | every minute | Hand durable submissions to a worker. `--limit=50 --recover-stale` |
| `app:reconcile-payment-submissions` | every minute | Verify references against Arc; record only proven settlements. `--limit=50 --mirror` (alias `eduflow:reconcile-payment-submissions`) |
| `app:dispatch-policy-evaluations` | every minute | Sweep queued JEV evaluations to background workers. `--sync --limit=20` |
| `app:recover-circle-notifications` | every minute | Re-queue verified webhook hints still unobserved. `--limit=50` |
| `app:dispatch-mandate-occurrences` | every minute | Classify due obligations for standing mandates (sessionless; no payment authority) |
| `eduflow:autonomous-pipeline-bridge` | every 5 minutes | Tuition receipt → JEV evaluation → vendor disbursement. `--payment= --invoice= --latest` |
| `lepton:reconcile` | ad hoc | Legacy hash reconciliation with honest verdicts. `--limit=200 --json --fix` |

```bash
php artisan lepton:reconcile
```

```text
  ✓  #7    vendor_payment      45.000000  verified    0xcecac1d9520c4815
  ~  #9    vendor_payment      12.500000  pending     0x1f0c9ab7d4e35c22
  ✗  #3    student_assistance 100.000000  reverted    0x59cbf4983d0e6ff1
  ?  #11   vendor_payment       8.250000  unresolved  0xb7e21c40a95d3381

  1 verified · 1 reverted · 1 unresolved · 1 pending · 0 provider-only · 0 unverifiable · 0 ledger-only
```

`--fix` marks a row failed **only** for `reverted`; unresolved rows are listed and left
untouched for a human. See [Safety & Readiness](../../institution/safety-readiness/#settlement-verdicts).

## Student lanes

| Command | What it does |
| --- | --- |
| `app:dispatch-student-tuition` | Dispatch queued tuition payment attempts (minute) |
| `app:reconcile-tuition-receipts` | Recovery for settled tuition movements no receipt covers yet |
| `app:dispatch-student-bill-payments` | Dispatch consented bill payments nobody took (minute) |
| `app:reconcile-student-bill-receipts` | Recovery for settled bill receipts |
| `student:generate-wallet` | Mint a Circle agent wallet for a student — `{student?} --list`. Capped at 5 agent wallets per blockchain (1 used by the treasury) |
| `student:fund-wallet` | Faucet-fund student wallets — `{student?} --all --list`. 20 USDC per drip, 429 after ~5 drips; each drip is logged |

## Developer demo & tooling

| Command | What it does |
| --- | --- |
| `app:demo` | One full autonomous cycle (85 USDC of real testnet USDC). `--student-email=juan@eduflow.test` (alias `eduflow:demo`) |
| `inspire` | Laravel's default motivational quote |

`app:demo` is not repeatable without re-funding (`LEPTON_DRIVER=fake` for iteration) and
is not the safe new payment lifecycle — see [Workflows](../../guides/workflows/#the-legacy-developer-path).
