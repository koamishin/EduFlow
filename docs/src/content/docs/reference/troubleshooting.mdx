---
title: Troubleshooting
description: Start with the visible symptom, inspect the right evidence, and avoid duplicate payments or destructive resets.
---

Find the symptom below. If a transfer may already have been sent, **do not send a
replacement until the existing attempt is resolved**.

## I can sign in, but the workspace is empty

Check that the installation has exactly one configured institution and your account has
the required role and permissions. The default developer seeder does not create a full
school finance dataset. Empty Collections or Supervisor pages can be expected.

For local fixtures, follow [Local setup](../../getting-started/local-development/).
Do not reset a deployed school database to populate a demo.

## A collection will not save

Check the source reference, document, currency, amount, and completed coverage period.
The same document or overlapping reports from one source can be refused to prevent
double counting. Inspect collection history before trying another reference or channel.

Saved records cannot be edited through the collection screen. A held/rejected review
is not reopened there. Arrange a reviewed correction instead of creating a duplicate.

## I cannot review my collection or payment

Independent review requires a different authorized person. For normal payment review,
check verified email, directly assigned permission, and enrollment of the current
authenticator. A changed factor can invalidate enrollment even when login still works.

See [Collections](../../guides/collections/) or
[Payment review](../../guides/payment-approvals/). Do not use the automatic bridge to
bypass a refused independent review.

## Planning or evaluations stay queued

A healthy web page does not prove a worker is running. Check:

1. Which queue connection the job uses.
2. Whether a worker listens on that connection and queue, including `default`.
3. Whether migrations, provider settings, and retry/timeout requirements are satisfied.
4. The run's last error, heartbeat, or evaluation timeline.

Planning is enabled directly in configuration and uses the default connection.
`EDUFLOW_BACKGROUND_FINANCE` is not a working switch in the current code.
The stock Compose web service supplies neither a general worker nor the scheduler.
See [Operations](../../guides/operations/).

## The plan holds a bill even though the wallet has money

Wallet balance is only one fact. Check the selected bill's reviewed evidence, remaining
allocation, restricted cash, reserve, other commitments, and snapshot expiry.
The planner checks selected bills cumulatively. A plan never grants payment authority.

## Payment says approved, accepted, or unknown

- **Approved:** check whether submission is enabled and the approval/funding evidence is still current.
- **Accepted:** the provider has a request handle; observation must resolve it to movement evidence.
- **Unknown:** inspect the existing provider handle and attempt. A timeout does not prove no send occurred.
- **Verified:** confirm whether this is full expected-payment matching or only the weaker legacy receipt check.

Keep the original identity and history. Do not delete an outbox row, release capacity,
or create a new request just to make the status disappear.

## Circle says `no agent session is active`

Check the intended network and operator session:

```bash
php artisan lepton:login --status
php artisan lepton:doctor --skip-transfer
```

Mainnet and testnet sessions are independent. A local wallet is not automatically a
Circle agent wallet the provider can sign for. Authentication needs a human operator;
do not put OTP login into a recovery worker.

## The Circle command fails before a provider request

Check that `LEPTON_CIRCLE_BIN` resolves to the intended executable for the service user.
A broken version-manager shim or a different worker `PATH` can fail before Circle is
contacted. The binary variable is `LEPTON_CIRCLE_BIN`, not a misspelled variant.

Some wallet-limit operations are mainnet-only. A testnet limit lookup error is not
itself proof that the testnet session or balance is absent.

## Faucet funding is rate-limited

Do not loop on a `429` response. Faucet quotas and wallet slots are external limits,
not guaranteed capacity. Use simulated data for iteration. Creating more operator
wallets just to avoid the limit can consume scarce wallet slots.

## A developer wallet will not submit

The current payment transport explicitly blocks developer-wallet execution pending
reviewed fee controls. An API key or newly selected driver does not remove that guard
or migrate an existing agent wallet. Do not weaken the guard to make a demo run.

## Frontend changes are missing

For the application, rebuild assets with `npm run build` or use the development server.
For this handbook, build in `docs/`, not the project root. GitHub Pages updates after
the docs change reaches `main` and the publishing workflow finishes.

## Before asking for help

Include the visible status, affected record IDs, software commit/version, enabled runtime,
and a sanitized error. Exclude passwords, OTPs, provider sessions, student data, and
private source documents. If money movement is uncertain, keep new sends stopped while
preserving observation and evidence.
