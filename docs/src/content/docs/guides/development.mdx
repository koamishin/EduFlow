## Conventions

- Follow existing files: descriptive names, constructor property promotion, explicit
  return types, curly braces, PHPDoc for types and array shapes.
- Money is always integer base units via `Amounts`; never floats, never `hexdec()` on
  chain quantities.
- Every new persistence boundary is evidence-bound: an immutable snapshot plus a
  canonical digest, and a second-person review where money or authority is involved.
- Update the area rules in `.ai/rules` (via the shared `record-rule` workflow) when you
  settle a durable, non-obvious decision.

## Quality toolchain

| Command | Tool | What it checks |
| --- | --- | --- |
| `composer lint` | Pint | PHP code style (fix in place) |
| `composer test:lint` | Pint | Style check (CI mode) |
| `composer phpstan` | PHPStan (level in `phpstan.neon`, baseline) | Static types |
| `composer rector` | Rector | Modernisation rules (dry-run) |
| `npm run check` | Vite-Plus | Frontend lint + format |
| `npm run types:check` | tsc | TypeScript |
| `composer test` | Pest | Config clear + lint + full suite |
| `composer ci` | all of the above | The full local gate, same order as CI |

## Testing

The project uses **Pest 5** with `pest-plugin-laravel`, `pest-plugin-browser` (Playwright,
group `browser`), `pest-plugin-agent` (one-off assertions), plus `pest-plugin-evals` and
`pest-plugin-phpstan` / `pest-plugin-rector`.

```bash
php artisan test --compact
php artisan test --compact --filter=JevAnalytics
php artisan test --compact --exclude-group=browser
```

Guidelines:

- The fake driver needs no network, credentials or cost, so the whole suite runs
  **offline**; tests that assert on receipts construct a chain stub that knows exactly one
  hash, so fabricated receipts cannot pass unnoticed.
- Use factories; check for custom states before building fixtures by hand.
- Adversarial AI tests run via the SDK's fakes — no provider keys in CI.

## One-off verification (Pest Agent Plugin)

Run a single behavioural check without creating a test file:

```bash
vendor/bin/pest --agent='$user = \App\Models\User::factory()->create(); visit("/login")->type("email", $user->email)->press("Log in")->assertPathIs("/dashboard");'
```

Use **single** outer quotes so the shell interpolates nothing. After any Blade, Livewire,
CSS or JS change, take a screenshot with the browser plugin and check for JavaScript
errors and mobile layout — install the browser plugin only with the user's permission
(it pulls Playwright and browser binaries).

## Debugging

- `php artisan pail` streams logs (started by `composer run dev`).
- `php artisan tinker` for REPL access.
- `php artisan lepton:doctor` — run first for any rail/session/treasury/ledger question.
- `php artisan app:finance-preview` — read-only treasury and cashflow view; always
  `can_execute=false`.
- Laravel Boost MCP tools (`database-schema`, `database-query`, `read-log-entries`,
  `browser-logs`) for schema and runtime inspection without a REPL.

## Adding a feature (checklist)

1. Read `.ai/rules/index.md` and the rule files covering the paths you will touch.
2. Search the installed-package docs before relying on an API; follow existing code.
3. Model + migration + factory + seeder (ask before creating models outside tests).
4. Action/service + tests (Pest) — including adversarial/negative cases for anything that
   touches money, authority or AI.
5. Filament resource or Inertia page + navigation/permissions (Shield).
6. `composer ci` and `npm run types:check` green; commit with a conventional message.
