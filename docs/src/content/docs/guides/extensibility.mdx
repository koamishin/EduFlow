## Where to put new work

| Change | Location | Generator |
| --- | --- | --- |
| A finance use case (capture, review, approve, authorise…) | `app/Actions` | `php artisan make:class` |
| A domain service (planning, verification, orchestration) | `app/Services` | `php artisan make:class` |
| A queued worker | `app/Jobs` | `php artisan make:job` |
| An evidence record | `app/Models` + migration | `php artisan make:model` (with factory + seeder) |
| An Inertia page | `resources/js/pages` + controller | Follow sibling TSX pages; use `make:controller` for the backend |
| An admin CRUD surface | `app/Filament/Resources` | `php artisan make:filament-resource` |
| A panel dashboard widget | `app/Filament/Widgets` or `app/Filament/Finance/Widgets` | `php artisan make:filament-widget` |
| An AI agent or tool | `app/Ai/Agents`, `app/Ai/Tools` | `php artisan make:class` |

## Filament resources

```bash
php artisan make:filament-resource Post
```

Then follow the existing structure in `app/Filament/Resources` — resources use separate
`Schemas`, `Tables` and `Pages` classes (form fields from `Filament\Forms\Components`,
table columns from `Filament\Tables\Columns`, actions from `Filament\Actions`, never the
sub-namespaced action classes).

Register per-panel access with Filament Shield (`php artisan shield:generate`), and add
navigation groups explicitly in the panel providers (`FinancePanelProvider`,
`AdminPanelProvider`).

## Inertia pages

Pages live in `resources/js/pages` as `.tsx` and are rendered from `routes/web.php` via
`Inertia::render('folder/page')`. Use **Wayfinder** route functions (`@/routes`, `@/actions`)
instead of hardcoded URLs; they are regenerated by `npm run build`
(`wayfinder:generate --with-form`).

Protect routes with the same middleware the feature needs (`auth`, `verified`,
throttling), and re-check authorisation server-side for every state-changing action.

## AI agents and tools

- **Tools** (`app/Ai/Tools`) are read-only inspection tools by default. Any tool that
  can cause money movement must be `Approvable` — implement `needsApproval()` by running
  the real policy evaluation and re-evaluate in `handle()` rather than trusting an earlier
  verdict.
- **Agents** (`app/Ai/Agents`) orchestrate tools and structured output. The deterministic
  answer is always computed first; a model may rephrase it, never replace it.
- Inspect each caller's failure behavior. A missing explanation can fall back in one
  path while publication or evaluation needs provider readiness in another.

## Modules

`nwidart/laravel-modules` provides the module system; `Modules/Blog` is the shipped
example and is enabled through `modules_statuses.json`.

```bash
php artisan module:make MyModule --no-interaction
php artisan module:enable MyModule --no-interaction
php artisan module:migrate --force --no-interaction
```

Keep new finance-domain work in `app/` (single-institution install, evidence-bound
records) rather than a new parallel domain; the “shadow pilot” is an operating mode, not
a separate application feature.

## Adding Artisan commands

```bash
php artisan make:command PrepareSomething
```

Give the command a `Signature`, `no-interaction`-safe options, and an
`InstallationInstitution::current()` fail-closed institution binding; use
`Amounts` for exact money and never touch the rail directly.
