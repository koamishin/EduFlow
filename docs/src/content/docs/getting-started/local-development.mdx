This guide is for contributors evaluating the application on their own machine.
Use [Install an instance](../installation/) for an operator-managed server.

**Goal:** a local app using simulated payments. No Circle account, funded wallet, or
AI provider is needed for the initial setup.

## Before you start

Use PHP 8.5, Composer 2, Node.js 22 or newer, and npm. Keep this instance separate from
school data and live credentials. The application and this documentation site have
separate dependency installations.

## Create a fresh development instance

```bash
git clone https://github.com/koamishin/OpenSinop.git opensinop
cd opensinop
composer install
cp .env.example .env
php artisan key:generate
npm ci
```

Use SQLite for the simplest local database. Create `database/database.sqlite` if it
does not exist, and set the evaluation settings before running the app:

```dotenv
APP_ENV=local
APP_DEBUG=true
DB_CONNECTION=sqlite
QUEUE_CONNECTION=database
LEPTON_DRIVER=fake
EDUFLOW_AUTONOMOUS_PIPELINE_ENABLED=false
EDUFLOW_AUTONOMOUS_PIPELINE_AUTO_DISBURSE=false
EDUFLOW_SUBMISSION_ENABLED=false
EDUFLOW_SUBMISSION_STOP=true
EDUFLOW_INSTITUTION_POLICY_ADVICE=false
```

Then apply schema, seed the default development users, and build the frontend:

```bash
php artisan module:enable Blog --no-interaction
php artisan migrate --no-interaction
php artisan module:migrate --no-interaction
php artisan db:seed --no-interaction
npm run build
composer run dev
```

`composer run dev` starts Laravel, Vite, a queue listener, and Pail logs. It **does not**
start the scheduler. Its queue list does not include every optional runtime, so inspect
the script before testing a particular queue.

The default seeder creates roles and local/testing users, not the full financial demo.
If no institution or authorized author exists, the optional default policy seeder skips
its draft. An empty dashboard after setup is therefore not necessarily an error.

## Choose your data path

### Test ordinary school setup

Use a fresh database, initialize one institution with `app:install`, and bootstrap a
unique first administrator. Do not first seed a development super admin: bootstrap
deliberately refuses a second super admin. See [Installation](../installation/).

### Try the legacy developer fixtures

Use only a disposable database without an installed school identity. These seeders add
legacy organization, student, wallet, budget, and bill fixtures; they are not production
onboarding and are not guaranteed to fit a separately initialized institution.

```bash
php artisan db:seed --class=EduFlowFinancialSeeder
php artisan db:seed --class=EducationDemoSeeder
php artisan db:seed --class=EduFlowPlanSeeder
```

The student and finance accounts below come from **EducationDemoSeeder**, not the
default `DemoUsersSeeder`:

| Account | Email | Local fixture password |
| --- | --- | --- |
| Student | `juan@eduflow.test` | `password` |
| Finance officer | `finance@eduflow.test` | `password` |

The default local `DemoUsersSeeder` instead creates `admin@admin.com` and
`user@user.com`. Never expose these fixture accounts on a deployed school instance.

## About `app:demo`

This command runs the legacy invoice/assistance cycle. It is not the ordinary reviewed
collections-to-plan workflow and not a safe shortcut for a pilot payment:

```bash
php artisan app:demo
```

Run it only with `LEPTON_DRIVER=fake` for local iteration. Under a real driver it can
move testnet funds. Its initial check only looks for the `Northstar Learning Center`
organization; it does not validate every required fixture. Partial seeding can omit
scenarios rather than reliably refusing.

## Daily development checks

```bash
npm run check
npm run types:check
composer test:lint
php artisan test --compact
```

Run narrow tests while developing, then the applicable full checks before a PR.
PHPStan and Rector scripts are also available in `composer.json`.

## Work on the handbook itself

```bash
cd docs
npm ci
npm run dev -- --host 127.0.0.1
```

Use the printed URL with `/OpenSinop/`, the configured project base. For a publishable
build, run `npm run build` and `npm run check:links` in `docs/`.
The docs toolchain needs Node `>=22.22.0` under the locked Astro version.

## Protect local data

Do not use `migrate:fresh` as a routine fix. It deletes records, including provider
configuration and evidence. A database reset also does not reverse any onchain transfer.
If you truly need new fixtures, use a new disposable database and keep previous evidence.
