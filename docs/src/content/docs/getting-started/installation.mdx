This guide is for the IT operator. Finance staff using an existing installation can
start with [Collections](../../guides/collections/) instead.

**Goal:** an accessible evaluation instance with one institution and a verified
administrator. Installing the web application does not approve it for real funds.

## Choose a setup path

| Your goal | Start here |
| --- | --- |
| Understand or contribute to the application | [Local setup](../local-development/) with simulated payments. |
| Run an isolated school evaluation | Follow Docker or host setup below. |
| Upgrade an existing instance | [Back up and update](#back-up-and-update) first. |

Before connecting credentials, read [Current limits](../../institution/safety-readiness/).
The experimental bridge defaults on; do not assume a fresh install cannot submit money.

## Requirements

- **Host installation:** PHP **8.5**, Composer 2, Node.js 22 or newer, and npm.
  Check the locked dependency requirements with Composer before deployment.
- **Database:** SQLite is convenient locally; the supplied Compose stack uses PostgreSQL 16.
- **Background work:** a durable database or Redis queue, a worker, and a scheduler.
- **Docker path:** Docker Engine and the Compose v2 plugin. The image supplies its PHP runtime.
- **Payment experiments:** separate approved Circle/Arc setup. Not needed for a first simulated trial.

PHP needs the appropriate PDO driver and the extensions required by `composer.lock`,
including BCMath, cURL, DOM/XML, fileinfo, mbstring, OpenSSL, and ZIP.
Do not bypass platform checks to make an unsupported host appear compatible.

## Docker: start an isolated web instance

Download the Compose file into a dedicated installation directory so updates use the
same project name and volumes:

```bash
mkdir opensinop
cd opensinop
curl -fsSLo docker-compose.yml https://raw.githubusercontent.com/koamishin/OpenSinop/main/docker-compose.yml
```

Review it before starting. Set institution identity, URL, a unique database password,
and an available image tag in this directory's `.env`. `EDUFLOW_VERSION` selects the tag;
do not assume `latest` points to the release you intend to test.

```dotenv
APP_NAME="Your School"
APP_ENV=production
APP_DEBUG=false
APP_URL=http://localhost:8000
APP_PORT=8000
DB_PASSWORD=replace-with-a-unique-password
EDUFLOW_INSTITUTION="Your School"
EDUFLOW_COUNTRY=PH
EDUFLOW_TIMEZONE=Asia/Manila
EDUFLOW_CURRENCY=PHP
```

The Compose file forwards only its listed environment values. It does **not** forward
all wallet, bridge, mail, or runtime settings from `.env`. Add the settings in
[Configure your instance](../configuration/) to the service environment through a
reviewed Compose override. A host `.env` entry alone does not configure an unlisted
container variable.

For an evaluation, include the fake driver, disabled payment/bridge flags, and submission
stop in that override **before** starting the app. Keep signing credentials absent.

```bash
docker compose config
docker compose up -d
docker compose logs app
```

The entrypoint attempts migrations and institution initialization. It can continue after
some failures, so inspect logs and confirm the institution exists; a healthy HTTP server
alone does not prove setup succeeded.

### Create the first administrator

```bash
docker exec -it opensinop php artisan app:bootstrap-admin \
  --name="School Operator" --email="operator@school.example"
```

The command asks for a password in the terminal, has no password argument, and refuses
an existing user or a second super admin. Configure mail, verify the email address,
and enroll MFA before opening staff access.

### Background services are separate

The supplied Compose stack runs `app`, `db`, and `redis`. Its default HTTP mode starts
FrankenPHP, not a general queue worker or the scheduler. Follow
[Run background services](../../guides/operations/) before relying on queued finance work.

## Host setup without Docker

Use a new, operator-controlled directory and database. Serve only Laravel's `public/`
directory through your chosen web server; never expose the project root or `.env`.

### 1. Install code and dependencies

```bash
git clone https://github.com/koamishin/OpenSinop.git opensinop
cd opensinop
composer install --no-dev --optimize-autoloader
cp .env.example .env
php artisan key:generate
npm ci
```

Generate `APP_KEY` only for this new installation. Keep it stable and backed up afterward.

### 2. Configure the instance

Set your URL, database, mail, sessions, cache, and payment isolation settings before
starting services. For example:

```dotenv
APP_NAME="Your School"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://finance.school.example
DB_CONNECTION=pgsql
DB_HOST=127.0.0.1
DB_PORT=5432
DB_DATABASE=opensinop
DB_USERNAME=opensinop
DB_PASSWORD=replace-with-a-unique-password
QUEUE_CONNECTION=database
SESSION_DRIVER=database
CACHE_STORE=database
LEPTON_DRIVER=fake
EDUFLOW_AUTONOMOUS_PIPELINE_ENABLED=false
EDUFLOW_AUTONOMOUS_PIPELINE_AUTO_DISBURSE=false
EDUFLOW_SUBMISSION_ENABLED=false
EDUFLOW_SUBMISSION_STOP=true
```

Check the full [configuration checklist](../configuration/). For an existing instance,
preserve the original key and credentials rather than replacing them with this example.

### 3. Apply schema and initialize the school

```bash
php artisan module:enable Blog --no-interaction
php artisan migrate --force --no-interaction
php artisan module:migrate --force --no-interaction
php artisan storage:link
php artisan app:install --institution="Your School" --country=PH \
  --timezone=Asia/Manila --currency=PHP --no-interaction
php artisan app:bootstrap-admin --name="School Operator" --email="operator@school.example"
npm run build
```

The installer saves one institution, roles, metadata, and conservative application
settings. It does not create wallets, provision demo finance records, or change the
separate automatic bridge configuration. Existing institutions need explicit reviewed
adoption; the command will not silently rename or replace them.

### 4. Start and verify services

Configure the web process and supervised background processes for your environment.
After final configuration, cache Laravel's configuration and views as appropriate,
then restart long-lived workers. See [Operations](../../guides/operations/).

## Before inviting staff

- Confirm exactly one institution and the intended currency/timezone.
- Verify email delivery and the first admin's MFA.
- Verify runtime isolation; do not rely on zero policy limits alone.
- Confirm private source uploads remain private.
- Confirm the worker and scheduler configuration, or explicitly keep the evaluation manual.
- Back up the database, private files, and application key, then test restoration.

## Back up and update

Keep the original installation directory, Compose project identity, volumes, and key.
Back up independently before changing code, images, or schema. The supplied updater
attempts a PostgreSQL dump but can continue after a failed dump; it does not provide a
complete recovery guarantee for every database or uploaded file.

:::danger[Preserve records and encryption keys]
Never use `migrate:fresh`, regenerate `APP_KEY`, or run `docker compose down -v` on an
instance whose records you need. Those actions can destroy data or make encrypted
settings unreadable. Resolve changes forward with reviewed backups and migrations.
:::

The optional `install.sh` and `install.ps1` wizards collect settings and have update
modes. Review the downloaded code before executing it. Selecting a driver in a wizard
does not fix missing Compose environment forwarding or certify payment readiness.
