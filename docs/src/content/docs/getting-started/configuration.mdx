Configuration lives in `.env` and the PHP files under `config/`. The most important
values are the finance runtime gates: the **submission, tuition, bill and mandate lanes
ship disabled** and are enabled only by an explicit operator decision.

## One exception: the Autonomous Pipeline Bridge is on by default

:::caution
`config/eduflow.php` defaults `eduflow.autonomous_pipeline.enabled` and
`eduflow.autonomous_pipeline.auto_disburse` to **true**, with a
`max_auto_disburse_usdc` ceiling of **50.00**, and `routes/console.php` schedules
`eduflow:autonomous-pipeline-bridge --latest` every five minutes. When the bridge runs
it resolves evidence, obtains the funding-window approval and — for a bill at or under
the ceiling — **sets `eduflow.submission.enabled` to true in-process**, submits it,
reconciles settlement and marks the invoice paid on verified movement.

`composer run dev` does not start the scheduler, so this does not fire in the default
development stack. It fires wherever the scheduler runs. If you are not ready for it,
set `EDUFLOW_AUTONOMOUS_PIPELINE_ENABLED=false` (and
`EDUFLOW_AUTONOMOUS_PIPELINE_AUTO_DISBURSE=false`), and do not start the scheduler until
you have read [Safety & Readiness](../../institution/safety-readiness/).
:::

## Core application

| Variable | Description | Default |
| --- | --- | --- |
| `APP_NAME` | Institution name used in titles and emails | `Laravel` |
| `APP_ENV` | `local`, `staging`, `production` | `local` |

| `CACHE_STORE` / `SESSION_DRIVER` | Cache and session backends | `database` |

## Lepton: Circle + Arc settlement

All Circle/Arc access goes through the [`yukazakiri/lepton-agent`](https://github.com/yukazakiri/lepton-agent)
gateways — application code never shells out to `circle` or `arc-canteen` directly.

```dotenv
# Driver selection:
#   fake      = in-memory simulated ledger (no CLI, credentials or funds; safe for demos/tests)
#   circle    = live rail using the Circle Agent Stack CLI + Arc network
#   developer = pure HTTP REST API using Circle Developer-Controlled Wallets
LEPTON_DRIVER=circle
LEPTON_CARCLE_BIN=circle
LEPTON_ARC_BIN=arc-canteen
LEPTON_CHAIN=ARC-TESTNET
LEPTON_CHAIN_ID=5042002
LEPTON_TREASURY_ADDRESS=0x…   # a Circle *agent* wallet — a local arc-canteen wallet cannot be signed for
LEPTON_RPC_URL=                 # optional RPC override
LEPTON_DRY_RUN=false

# Optional: LEPTON_DRIVER=developer (REST only, zero CLI binaries)
LEPTON_CIRCLE_API_KEY=
LEPTON_ENTITY_SECRET=
LEPTON_WALLET_SET_ID=
LEPTON_CIRCLE_API_URL=https://api.circle.com/v1/w3s
```

:::caution[Driver version boundary]
The application targets Lepton **v3** (`composer.json` requires `^3.0@rc`; the lock file
installs `v3.0.0-rc.1`, a prerelease). Pin the version and validate it before a school
release. Existing Agent Stack wallets are not automatically reachable through a
Developer-Controlled Wallets API key — the REST drivers are a separate integration
option, not a migration.
:::

### Verified Circle notifications (opt-in)

`POST /api/webhooks/circle` answers `404` unless **both** `LEPTON_WEBHOOKS_ENABLED=true`
and `LEPTON_DRIVER` is `developer` or `circle-rest`.

| Variable | Purpose |
| --- | --- |
| `LEPTON_WEBHOOKS_ENABLED` | Master switch for the webhook endpoint |
| `LEPTON_WEBHOOK_SUBSCRIPTIONS` | Comma-separated subscription IDs this deployment may accept |
| `LEPTON_WEBHOOK_MAX_AGE_SECONDS` | Acceptance window for a signed timestamp (default `86400`) |

A verified event is stored once (unique `notificationId` + payload digest) and only
queues observation — it never creates or submits a payment, and never settles one; the
response is `202` with `settlement_verified: false`.

Ingestion is contained: the handler requires `X-Circle-Signature` and `X-Circle-Key-Id`
(`401` without them), caps the payload at 1 MiB (`413`), verifies the raw body against
the notification key (`401` on failure), accepts only `transactions.inbound`,
`transactions.outbound` and `webhooks.test` (`422` otherwise), validates the chain and
UUID-shaped transaction id (`422`), and requires a durable `database`/`redis` queue
(`503` otherwise). See [Security](../../guides/security/#webhook-ingestion).

## Finance runtime gates

Every switch below defaults **off**. Turning one on is an operator decision, not a
consequence of anything else.

### Student tuition (student → college, outbound)

| Variable | Effect |
| --- | --- |
| `EDUFLOW_TUITION_SUBMISSION_ENABLED` | Sign new consented transfers (requires a rail that can enforce the fee ceiling) |
| `EDUFLOW_TUITION_OBSERVATION_ENABLED` | Resolve already-accepted transfers on chain |
| `EDUFLOW_TUITION_SUBMISSION_STOP` | Stop switch — halts new submissions, keeps recovery running |
| `EDUFLOW_TUITION_AUTO_INTAKE` | Reconcile settled movements into Collections unattended (requires immutable consent + verified proof + a named non-payer intake owner) |
| `EDUFLOW_TUITION_INTAKE_OWNER_ID` | Verified finance account credited as receipt maker; must not be a payer |
| `EDUFLOW_TUITION_QUEUE_CONNECTION` | Durable queue connection for the lane (default `database`) |

### Student bills (inbound intake)

| Variable | Effect |
| --- | --- |
| `EDUFLOW_BILL_SUBMISSION_ENABLED` | Gate new submissions in the bill lane |
| `EDUFLOW_BILL_OBSERVATION_ENABLED` | Resolve transfers that already exist |
| `EDUFLOW_BILL_SUBMISSION_STOP` | Halt new sends while leaving reconciliation and recovery running |
| `EDUFLOW_BILL_AUTO_INTAKE` | Unattended receipt reconciliation |
| `EDUFLOW_BILL_PILOT_IDS` | Explicit comma-separated allow-list of bill IDs; a bill absent from it is never sent |

### Vendor payment submission and standing mandates

| Variable | Effect |
| --- | --- |
| `EDUFLOW_SUBMISSION_ENABLED` | Hand durable payment submissions to a worker |
| `EDUFLOW_SUBMISSION_STOP` | Hold new submissions without erasing evidence or releasing a hold |
| `EDUFLOW_SUBMISSION_TRANSPORT` | `auto` treats a Circle driver as the asynchronous agent wallet it is; `synchronous` forces the older hash-returning contract |
| `EDUFLOW_MANDATE_ENABLED` | Whether any automatic release may be recorded at all |
| `EDUFLOW_MANDATE_ALLOWANCE` | Whether a reviewed mandate may carry a nonzero per-occurrence ceiling — until on, every mandate authorises nothing |

### Institution finance and policy

| Variable | Effect |
| --- | --- |
| `EDUFLOW_INSTITUTION_ID` | Installation institution identity; required outside local/testing |
| `EDUFLOW_INSTITUTION_POLICY_ADVICE` | Master switch for institution policy advisory calls |
| `EDUFLOW_POLICY_CLASSIFICATION_ENGINE` | `text` or `jev` classification engine |
| `EDUFLOW_BACKGROUND_FINANCE` | Read-only planning runtime; enabled in `config/eduflow.php` and needs a durable queue plus a supervised scheduler to do work |
| `EDUFLOW_DISPLAY_CURRENCY` | Local currency shown beside USDC settlement amounts (default `PHP`) |
| `EDUFLOW_MAX_RATE_AGE_SECONDS` | Maximum age of a rate source (default `900`) |
| `EDUFLOW_AUTONOMOUS_PIPELINE_ENABLED` | Autonomous Pipeline Bridge (tuition receipt → JEV evaluation → vendor disbursement). **Defaults to `true`** |
| `EDUFLOW_AUTONOMOUS_PIPELINE_AUTO_DISBURSE` | Whether the bridge may submit without manual authorisation. **Defaults to `true`** |
| `EDUFLOW_AUTONOMOUS_PIPELINE_MAX_USDC` | Auto-disburse ceiling for the bridge (default `50.00`); a bill above it is held for manual authorisation |
| `EDUFLOW_AUTONOMOUS_PIPELINE_MAKER_ID` / `_REVIEWER_ID` | Staff IDs the bridge attributes maker and reviewer roles to (defaults `4` / `1`) — set these to your own reviewed users |

:::caution[Never run `composer require`/`update` without `--no-scripts`]
The `post-update-cmd` script runs `php artisan install:features`, which consumes the
feature-toggling (chisel) scaffolding: it strips `/* @chisel-* */` markers and deletes
`chisel.php`, `chisel-paths.php` and `app/Console/Commands/InstallFeaturesCommand.php`.
No app code is lost and tests still pass, but the tooling is gone. Recover with
`git checkout -- <files>`.
:::

## AI providers (optional)

OpenSinop runs with none of these. Every model call is fail-closed: a missing key, an
unreachable endpoint, malformed output or a timeout resolves to “no advisory available”,
and the deterministic engine proceeds alone. A model outage degrades the product; it
never blocks a payment.

```dotenv
# Default provider: local (an OpenAI-compatible endpoint such as Ollama, vLLM, LiteLLM)
AI_PROVIDER=local
AI_LOCAL_URL=http://localhost:11434/v1
AI_LOCAL_MODEL=ag/gemini-3.8-flash-high

# Generic OpenAI-compatible gateway
OPENAI_COMPATIBLE_URL=https://your-gateway.example.com/v1
OPENAI_COMPATIBLE_MODEL=llama3.1
OPENAI_COMPATIBLE_API_KEY=…

# Hosted providers
# OPENAI_API_KEY=sk-…
# ANTHROPIC_API_KEY=sk-…
# GEMINI_API_KEY=…
```

Providers can also be managed from **Settings → AI Providers** in the admin panel; API
keys are encrypted at rest with `APP_KEY` and never rendered back into the edit form.
See [Security](../../guides/security/#ai-boundaries) for the authority boundaries.

## Config files

| File | Controls |
| --- | --- |
| `config/eduflow.php` | Finance runtime gates, queue wiring, display currency, rate freshness, autonomous pipeline |
| `config/lepton.php` (package) | Chain, driver, treasury, RPC and webhook verification |
| `config/ai.php` | Provider registry and default models |
| `config/fortify.php` | Authentication features (2FA, email verification, profile) |
| `config/permission.php` | Spatie Permission / Filament Shield role and permission model |
| `config/filament-activity-log.php` | Activity log, privacy mode and risk scoring |
| `config/multitenancy.php` | Reserved for the future multi-institution hosting model — not enabled |

## Campus quick resources

Cards beneath “My Assistance Requests” on the student dashboard are configured in
`config/eduflow.php` under `resources`. A card becomes clickable only once its `url` is
set; entries without one render as a muted placeholder rather than a dead link. `icon`
must be a kebab-case Lucide icon name; unknown names fall back to a generic icon on the
client.
